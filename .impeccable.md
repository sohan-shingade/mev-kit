## Design Context

### Users
MEV strategy developers, quant trading desks, and MEV searchers on Solana. They are highly technical, read tabular data at speed, monitor real-time pipelines, and iterate on strategy parameters. They use the tool daily for backtesting, paper trading, and live execution. They expect information density — every pixel should earn its place.

### Brand Personality
**Technical. Powerful. Clean.**

The interface should feel like a weapon — fast, data-rich, zero decoration. It respects the user's intelligence and doesn't hide complexity behind simplification. The tool is for professionals who already know what they're looking at.

### Emotional Goal
**Speed & urgency.** Every millisecond counts in MEV. The UI should feel responsive, immediate, alive. When a pipeline is running, the user should feel the pulse of data flowing. When backtesting, results should appear instantly. No loading spinners that last more than a beat.

### Aesthetic Direction
- **Dark mode only.** No light mode — this is a trading terminal, not a consumer app.
- **Data density over whitespace.** Bloomberg Terminal's information density, not Linear's breathing room. Pack more data per screen, but keep it scannable.
- **Strong visualization.** Dune Analytics-style charts and data exploration. Charts should be large, readable, and tell a story. Not decorative — functional.
- **Neon signals on dark canvas.** Green for profit, red for loss, amber for warnings, indigo for interactive elements. These colors pop against the dark background and create instant recognition.
- **Monospace for data, sans-serif for UI.** Inter for labels and navigation, SF Mono for every number, price, address, and metric.

### Anti-References
- No rounded pastel cards (Notion, Slack)
- No excessive whitespace (Apple marketing pages)
- No playful illustrations or empty states with cute graphics
- No light backgrounds or muted palettes

### Design Principles

1. **Every pixel is information.** If a UI element doesn't convey data or enable an action, remove it. Decorative elements waste screen space that could show another metric.

2. **Scannable at a glance.** A user should understand the pipeline state, P&L, and opportunity flow without reading any text — purely from color, position, and number formatting.

3. **Speed is a feature.** Interactions must feel instant. No animations longer than 150ms. No loading states that block interaction. Optimistic updates where possible.

4. **Color is semantic.** Green = profit/success/go. Red = loss/failure/stop. Amber = warning/attention/spread. Indigo = interactive/editable/clickable. Never use these colors decoratively.

5. **Progressive disclosure, not simplification.** Show the critical data by default. Let power users dig deeper (expand panels, open details, see raw data). Never hide information to look cleaner.

### Color Palette
- Backgrounds: `#1a1a2e` (main), `#16213e` (panels), `#12122a` (sidebar), `#252547` (active)
- Borders: `#2a2a4a`
- Text: `#e0e0e0` (primary), `#7f8ea3` (secondary)
- Accents: `#00e676` (green/profit), `#ef5350` (red/loss), `#ffab00` (amber/warning), `#6366f1` (indigo/interactive)

### Typography
- UI: Inter, -apple-system, sans-serif
- Data: SF Mono, Monaco, Cascadia Code, monospace
- Labels: 10-11px, uppercase, letter-spacing 0.05em, text-secondary color
- Data values: 11-14px, monospace, bold, color-coded

### Spacing
- Panel gaps: 2px (tight grid)
- Internal padding: 8px (compact)
- Section gaps: 8-12px
- Dense Pro aesthetic — minimal chrome, maximum content
